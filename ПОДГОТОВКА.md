# Подготовка к демоэкзамену 09.02.07 (Программист)

## 1. Что такое экзамен

Тема: **магазин обуви**. Нужно сделать базу данных и программу (окна на компьютере) для неё.
Интернет: максимум 15 минут, на общем компьютере. **ИИ, чаты, GitHub и StackOverflow запрещены**,
за экраном следят эксперты. Поэтому всё нужно уметь делать руками.

| Уровень | Время | Модули | Баллы |
|---|---|---|---|
| ПА (промежуточная) | 1 ч 30 мин | 1, 2 | 25 |
| ГИА базовый | 3 ч | 1, 2, 3 | 50 |
| ГИА профильный | 4 ч | 1, 2, 3, 4 | 75 (+25 вариативная часть колледжа) |

Где больше всего баллов: М3 (24 балла), М4 (23 балла), разработка кода в М2 (11 баллов).
За каждое действие ставят 2 балла (полностью), 1 балл (с ошибками) или 0.

## 2. Модули

### Модуль 1. База данных (50 мин, 10 баллов)
- [ ] Таблицы в **3-й нормальной форме**: повторяющиеся значения (роль, поставщик, производитель,
      категория, статус, пункт выдачи) вынесены в отдельные таблицы-справочники.
- [ ] Первичные ключи (`PRIMARY KEY`) и внешние ключи (`FOREIGN KEY` / `REFERENCES`).
- [ ] Единый стиль имён: латиница, маленькие буквы.
- [ ] Импорт данных из xlsx (папка `import`).
- [ ] **ER-диаграмма в PDF**: таблицы, связи, ключи (как на фото с доски, экспорт из DbVisualizer / DB Browser).
- [ ] **Скрипт БД** (`.sql` файл), это `schema.sql`.

Ловушки в данных: даты, которых не бывает (30.02), пробелы в конце слов («Новый »),
заказ 2022 года среди заказов 2025-го, у части товаров нет фото.

### Модуль 2. Алгоритм и первое приложение (40 мин, 15 баллов)
- [ ] **Блок-схема по ГОСТ 19.701-90** в PDF (например, алгоритм входа в систему).
      Овал = начало/конец, прямоугольник = действие, ромб = условие, параллелограмм = ввод/вывод.
- [ ] Стиль из Приложения 3 (шрифт, цвета), иконка приложения, логотип на главном окне.
- [ ] Имена в коде: CamelCase (C#/Java) или snake_case (Python). Одна команда на строку.
- [ ] **Окно входа**: логин + пароль из БД, кнопка «Войти как гость».
- [ ] ФИО пользователя в правом верхнем углу, кнопка «Выход» назад к окну входа.
- [ ] **Список товаров**: фото (если нет, то `picture.png`), наименование, категория, описание,
      производитель, поставщик, цена, единица измерения, количество, скидка.
- [ ] Подсветка строк:
  - скидка **больше 15%**: фон `#2E8B57`;
  - есть скидка: старая цена **перечёркнута красным**, рядом новая цена чёрным;
  - количество = 0: строка **голубая**.
- [ ] Документ **.docx со скриншотами** работы программы.

### Модуль 3. Поиск, фильтр, редактирование (1 ч 30 мин, 25 баллов)
- [ ] Кнопка «Назад» и правильный заголовок на каждом окне.
- [ ] Сообщения об ошибках с заголовком и иконкой (Ошибка / Предупреждение / Информация),
      понятный текст: что не так и как исправить.
- [ ] Только у менеджера и админа:
  - поиск по всем текстовым полям, сразу при вводе;
  - сортировка по количеству на складе (по возрастанию и по убыванию);
  - фильтр по поставщику, первый пункт «Все поставщики»;
  - всё работает вместе и без кнопки «Найти».
- [ ] Только у админа, форма товара в отдельном окне:
  - «Добавить товар» и клик по товару для редактирования;
  - категория и производитель в выпадающих списках;
  - цена с копейками, не меньше 0; количество не меньше 0;
  - ID не показывается при добавлении, при редактировании только для чтения;
  - загрузка фото: копия в папку программы, размер 300×200, путь в БД, старое фото удаляется;
  - **нельзя открыть второе окно редактирования**;
  - удаление товара, но **не того, что есть в заказе**;
  - после изменений список обновляется.
- [ ] Комментарии только в неочевидных местах кода.

### Модуль 4. Заказы (1 ч, 25 баллов, только профильный уровень)
- [ ] Кнопка «Заказы» у менеджера и админа, список заказов.
- [ ] У админа: добавить, редактировать, удалить заказ (поля: артикул, статус списком,
      адрес пункта выдачи, дата заказа, дата выдачи).
- [ ] **Git**: залить в репозиторий исходники (не архивом), exe-файл, скрипт БД, картинки и документы.

## 3. Порядок обучения

1. **SQL-основы** (1–2 дня): `CREATE TABLE`, `INSERT`, `SELECT ... JOIN`, `UPDATE`, `DELETE`.
   Тренировка: разобрать `schema.sql` и построить базу из `import2` (мебель) самому.
2. **ER-диаграмма и блок-схема** (полдня): экспорт в PDF из DbVisualizer, блок-схема в draw.io.
3. **Окно входа + список товаров** (2–3 дня): главное в М2.
4. **Поиск/фильтр/сортировка + форма товара** (3–4 дня): М3.
5. **Заказы + git** (2 дня): М4.
6. **Пробный экзамен на время**: всё с нуля по второму варианту (`import2`), без подсказок.

На экзамене делай по порядку и сохраняй результат после каждого модуля:
неидеальная программа, которая запускается, лучше, чем красивая, которая падает.
